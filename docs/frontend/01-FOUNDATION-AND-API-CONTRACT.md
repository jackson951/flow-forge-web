# 01 — Foundation and API Contract

**Status:** COMPLETE (2026-10-03) — evidence below; see [00-FRONTEND-ROADMAP.md](00-FRONTEND-ROADMAP.md)

## Objective

Make the scaffold talk to the real backend correctly: one typed API client for `/api/v1`, contract types that match the backend exactly, the backend error envelope, workspace-aware routing and query keys, and a mock layer (MSW) for tests and offline development.

## Why This Part Exists

Every later part depends on the contract. The scaffold predates the backend and gets paths, auth, enums and shapes wrong (see roadmap "Scaffold gaps"); fixing that once, centrally, avoids each feature inventing its own fetch logic.

## Scope

API client, contract types, error model, query-key conventions, URL structure, environment config, MSW setup, dev proxy, removal of scaffold types that do not match.

## Functional Requirements

| ID | Requirement |
| --- | --- |
| FR-01.1 | Base URL `VITE_API_BASE_URL` defaults to `/api/v1`; the Vite proxy forwards `/api` to `http://localhost:3000`; the production build is same-origin behind nginx (Part 14). |
| FR-01.2 | A single `api` client: JSON in/out, `credentials: 'include'`, attaches `Authorization: Bearer <token>` from the in-memory session (token store provided here, filled by Part 02), forwards an optional `Idempotency-Key`, supports `AbortSignal`. |
| FR-01.3 | `ApiError` carries `status`, `error`, `message` (string or list), `details`, `requestId`, `retryAfterSeconds` (from `Retry-After`); helpers `isNotFound`, `isConflict`, `isRateLimited`, `isValidation`. Network failure and non-JSON bodies become an `ApiError` with status 0 / the HTTP status. |
| FR-01.4 | Contract types in `src/types/api.ts` match the backend: enums `RunStatus`, `StepStatus`, `WorkflowStatus` (`DRAFT\|PUBLISHED\|ARCHIVED`), `WorkspaceRole`, `ConnectionStatus`, `TriggerSource`, `ErrorCategory`, `IntegrationProviderKey` (`GITHUB\|SLACK\|MICROSOFT`); response shapes for auth, workspaces, members, workflows, versions, node types, runs, steps, dashboard, integrations. |
| FR-01.5 | Types are **generated** from the backend OpenAPI document (`openapi-typescript` against `/api/docs-json`, checked into `src/types/openapi.ts`, regenerated by `npm run api:types`); `api.ts` re-exports or narrows them. The 20 operations without typed success schemas get hand-written types, each with a comment pointing to the backend service that produces it. |
| FR-01.6 | Workflow definition types mirror the backend engine: `{ schemaVersion: 1, nodes: [{ key, kind, type, config, position? }], edges: [{ from, to, branch? }] }`, plus exported limits (50 nodes, 100 edges, 256 KB, key pattern). |
| FR-01.7 | URL structure: tenant pages live under `/w/:workspaceId/...` (`/w/:id`, `/w/:id/workflows`, `/w/:id/workflows/:workflowId`, `/w/:id/runs`, `/w/:id/runs/:runId`, `/w/:id/integrations`, `/w/:id/settings`); `/` redirects to the last-used workspace (Part 03). |
| FR-01.8 | Query keys: every tenant key starts with `['ws', workspaceId, …]`, so switching workspace never shows cached data from another workspace and a workspace's cache can be cleared in one call. |
| FR-01.9 | MSW handlers for every endpoint used, with fixtures typed against the contract; used by Vitest and optionally by `npm run dev:mock`. |
| FR-01.10 | Remove or rewrite scaffold code that encodes the wrong contract (cookie-only auth, `/dashboard` without workspace, `ACTIVE`, `trigger` field, …). |

## Technical Requirements

- No fetch outside `src/lib/api-client.ts`; feature `api/*.ts` files only map endpoints to functions.
- `zod` used to validate environment config and form input, not to re-validate every API response (generated types are the contract); one runtime check: the error envelope.
- Contract test: a script compares the generated types with a live backend's `/api/docs-json` (CI uses the committed file; drift shows up as a diff when regenerated).

## Backend Endpoints

All of them (types only); none called for real until Part 02.

## Testing Requirements

Unit tests for the client (headers, bearer, idempotency key, 204, error parsing incl. `Retry-After`, network error), query-key helpers, URL builders; MSW fixtures type-check.

## Deliverables

Rewritten `api-client.ts`, `types/openapi.ts` + `types/api.ts`, `lib/query-keys.ts`, `lib/routes.ts` (typed URL builders), MSW setup in `src/test/msw/`, updated `.env.example`, README contract section.

## Acceptance Criteria

| ID | Criterion | Verification |
| --- | --- | --- |
| AC-01.1 | Client sends requests to `/api/v1`, with bearer token and credentials, and parses the backend error envelope including `details` and `Retry-After` | Unit tests |
| AC-01.2 | Types generated from the running backend's OpenAPI document; `npm run api:types` reproduces the committed file | Command run |
| AC-01.3 | Every enum and response shape used by the UI matches the backend (no `ACTIVE`, no `trigger` field, no `id` on nodes) | Typecheck + review against Swagger |
| AC-01.4 | Every tenant query key contains the workspace id | Unit test over `queryKeys` |
| AC-01.5 | MSW serves every endpoint the UI uses; tests run with no backend | `npm test` offline |
| AC-01.6 | Against the real backend, `GET /api/v1/health/ready` succeeds through the dev proxy | Browser/network check |

## Out of Scope

Login UI and refresh logic (02), page implementations.

## Dependencies

Backend running locally for type generation and AC-01.6.

## Risks / Design Questions

- 20 untyped success bodies: hand-written types can drift. Mitigation: MSW fixtures copied from real responses; long-term, typed DTOs in the backend (backend release report, Future improvements).

## As implemented

| Area | Implementation |
| --- | --- |
| Client | `src/lib/api-client.ts`: `/api/v1` resolved against the page origin (same origin in dev and production; also what Node's fetch needs in tests), JSON, `credentials: 'include'`, bearer token from `src/lib/access-token.ts` (memory only), `Idempotency-Key`, `AbortSignal`, query builder that drops `undefined`. `ApiError` carries `status`, `error`, `messages[]`, `details` + `code`, `requestId` (body, else `x-request-id`), `retryAfterSeconds`; helpers `isNotFound`, `isConflict`, `isRateLimited`, `isValidation`; network failure → status 0; aborts pass through |
| Types | `src/types/openapi.ts` generated by `npm run api:types` (`scripts/generate-api-types.mjs`, cross-platform; `API_DOCS_URL` overrides). `src/types/api.ts` re-exports auth, workspace, member and request DTOs from it and hand-writes the shapes Swagger does not type (workflows, versions, validation issues incl. all 23 issue codes, node types, runs, steps, error descriptions, dashboard, integrations, pickers), each section naming its backend source |
| Definition | `features/workflows/types/workflow-definition.ts`: `{ schemaVersion: 1, nodes: [{ key, kind, type, config, position? }], edges: [{ from, to, branch? }] }`, `EMPTY_DEFINITION`, `DEFINITION_LIMITS`, `NODE_KEY_PATTERN` |
| URLs | `src/lib/routes.ts` (`paths`, `patterns`, `safeNextPath`); router: `/` → `WorkspaceRedirect` (first workspace; Part 03 adds last-used), tenant pages under `/w/:workspaceId`; sidebar links built from the current workspace |
| Query keys | `src/lib/query-keys.ts`: tenant keys `['ws', workspaceId, …]`; `queryKeys.ws(id)` clears a workspace |
| Feature APIs | Rewritten against the real endpoints: `auth`, `workspaces` (new), `workflows` (+ versions, node types), `runs`, `integrations` (+ pickers), `dashboard` |
| Mocks | `src/test/msw/`: typed fixtures, a handler per endpoint (tenant routes 404 for unknown workspaces, like the backend), `apiError()` helper; `setup.ts` fails any unhandled request. `src/test/jsdom-environment.ts` keeps Node's `AbortSignal` under jsdom (Node's fetch rejects jsdom's) |
| Removed | Cookie-only auth assumptions, `ACTIVE` status, `trigger` + `nodes[].id` definition shape, invented node types (`webhook.received`, `microsoft.sendMail`), paths without workspace, `/dashboard` without workspace |

### Notes

- Hand-written response types were derived from the backend source, not from captured responses (capturing would have meant writing test users into the developer's database). They are checked by typecheck and by the MSW fixtures now, and against live responses as each page is wired (Parts 02+).
- Found while reading the backend, recorded in later specs: refresh returns tokens only, so session restore also needs `GET /auth/me` (Part 02); a node may have at most one incoming edge (`MULTIPLE_INCOMING`, Part 05).
- Visual direction for later parts: [design/DESIGN-DIRECTION.md](design/DESIGN-DIRECTION.md) — only screens backed by the real API are built.
